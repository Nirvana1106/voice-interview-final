# 面试练习室：语音模拟面试

三轮模拟面试应用的候选实现。前端为原生 HTML/CSS/JavaScript，后端为 FastAPI，数据库为 PostgreSQL；三者通过 Docker Compose 部署。问题通过服务端的 OpenAI 兼容流式对话接口生成，浏览器使用语音合成播报问题、使用 Web Speech API 从麦克风识别回答。确认后的文字才会保存并进入下一题上下文。

当前已通过 25 项前端逻辑回归及用户 Docker 环境中的 26 项后端/数据库测试。真实模型正式批次 21 次全部成功，延迟数字达标；用户确认语音识别与录屏检查，保留数据卷重建后 7 场完整问答仍在。结果来源、验证限制与发布状态见 [验收记录](docs/validation.md) 和 [交付状态](docs/delivery-status.md)。

## 启动

1. 从 [Docker 官方页面](https://www.docker.com/products/docker-desktop/)安装并启动 Docker Desktop（含 Compose）。无需在验收环境另装 Python、Node.js 或 PostgreSQL；构建与测试会自动拉取所需镜像并安装后端依赖。
2. 复制 `.env.example` 为 `.env`，填写自己可用的 `MODEL_API_KEY`。`MODEL_BASE_URL` 是兼容 Chat Completions 的 API 根地址，示例为 `https://api.openai.com/v1`；`MODEL_NAME` 默认 `gpt-4o-mini`，可改成该服务确实可用的模型。不要把真实密钥提交到仓库。
3. 在本目录执行 `docker compose up --build -d`，或在任意 PowerShell 目录运行本项目 `scripts/Start-Project.ps1`（例如用 `powershell -NoProfile -ExecutionPolicy Bypass -File` 加脚本的完整路径）。等待数据库健康检查和后端初始化完成，然后打开 <http://localhost:8080>。如改了 `PORT`，用对应端口。
4. 使用预置账号登录：`demo-alice` / `InterviewDemo123!`，或 `demo-bob` / `InterviewDemo456!`。这些是公开的验收账号，仅用于本地测试；可以在 `.env` 中调整对应密码。首次启动自动建表并写入两个账号。

后端镜像构建时会先执行 Python 语法检查和核心逻辑单元测试，失败则停止构建。

有 Docker 后可先运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Project.ps1`，执行隔离的自动化测试，不需要真实模型密钥。`-ExecutionPolicy Bypass` 只对这次 PowerShell 进程生效。测试数据库与普通应用的数据卷分开，详见 [自动化测试说明](docs/testing.md)。

若 Docker Hub 在当前网络不可达，可按 [自动化测试说明](docs/testing.md) 临时设置 `IMAGE_REGISTRY` 选择自己信任的可访问镜像站；默认仍使用 Docker Hub。此设置只改变基础容器镜像来源，不改变模型服务地址。

当前交付包包含完整项目源码和测试，但不包含 Docker Desktop 安装程序或容器镜像。本机已有 Docker CLI 和 Compose；2026-10-06 用户本人在 Windows PowerShell 运行一键脚本，前端检查与后端/数据库测试均成功退出，脚本报告 `Automated checks passed`。当前 Codex 工具账户仍无权连接 Docker 引擎；该自动化结果由用户终端截图确认，不代表真实语音、模型性能或生产容器持久化验收通过。

PowerShell 下复制配置文件可用 `Copy-Item .env.example .env`。若模型密钥缺失、无效或服务超时，页面会显示错误和重试按钮，已确认的问答不会丢失。

本机实际连通的配置为百炼北京地域 `MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1` 与 `MODEL_NAME=qwen-plus`，密钥使用该服务商的 API Key。其他地域或服务商须使用其对应根地址、可用模型及密钥。配置修改后重新执行启动脚本；可从任意目录用完整路径运行 `scripts/Test-Model-Connection.ps1`，它在后端容器内发出一条极短的真实请求，只输出连接状态，不显示密钥。

第二题仅使用上一轮已确认回答作为回答事实来源，要求模型引用真实片段后追问；开头引用不符会中止并提示重试，失败尝试保留在性能记录中。引用检查不改写模型正文，也不自动隐藏重试；其耗时包含在实际页面首字延迟中。

## 核心流程

选择 `samples.json` 中任一组虚构的岗位描述与经历，或自行填写资料，开始面试。点击开始后，后端才发起第一道真实模型请求；页面逐片显示模型返回的正文，并尽早按片段播报。点击“重播问题”可重新听当前完整问题，点击“停止播报”可停止，后续流片段不会再次开启播报。点击麦克风作答时会先停止问题播报，浏览器请求麦克风权限并显示识别结果；先停止录音，等待最后识别结果返回，再校对或修改文字，点击确认后才保存答案并生成下一题。第二题的提示词明确要求针对第一题的已确认回答追问。第三题回答确认后状态变为“已完成”。

刷新或重新登录时，应用恢复最近的进行中面试；已生成的问题和已确认回答从数据库加载。遇到尚未生成完的问题，可点“重试生成问题”。历史列表可回看完整问答。两个账号的数据由每个后端接口按用户 ID 检查，不能通过更换 URL 读取对方的会话。重复确认同一答案只返回已保存结果，不会推进第二次；不同文字的重复提交会返回冲突。

语音验收推荐桌面版 Chrome 或 Edge，使用 `localhost` 访问，保持麦克风权限可用并联网。浏览器需支持 `speechSynthesis` 与 `SpeechRecognition`/`webkitSpeechRecognition`。后者可能由浏览器调用其在线识别服务。麦克风拒绝授权、识别失败或浏览器不支持时，页面给出文字输入途径；播报失败时保留问题文字。这些备用方式供异常处理使用，正常验收仍要实际操作播报和麦克风识别。原始音频不会上传到本项目后端或持久化。

## 架构与关键取舍

- Nginx 提供前端并反向代理 `/api/`；关闭问题流的代理缓冲。服务端密钥只在后端环境变量中，前端只收到生成的问题片段。
- 后端使用一进程和单会话生成锁，确保同一轮不会并行生成两道问题。数据库保存面试配置、当前轮次、已生成问题、已确认回答、账号会话及每次请求的性能记录。
- PostgreSQL 数据位于 `interview_db` 卷。保留该卷重新创建容器后，业务数据仍存在。不要执行 `docker compose down -v`，否则会删除数据卷。
- 模型请求使用 `stream=true`，仅把真实正文增量推送到页面。响应头、心跳、角色字段和非正文内容都不算 TTFT。模型失败或浏览器断开时，当前生成可重试，已完成轮次不回滚。
- 使用浏览器语音能力而非额外的付费 TTS/STT 服务，以便与任意兼容模型供应商搭配。实际可用性依赖指定浏览器、麦克风与联网环境。

第三方依赖来自官方镜像与包：PostgreSQL、Nginx、Python、FastAPI、Uvicorn、asyncpg、httpx；语音能力来自浏览器内置 Web Speech API。页面没有使用第三方图片、图标包或预制业务组件。账号与权限、面试状态机、模型流解析、语音控制、性能采集和界面均为本项目自行实现；模型推理由用户配置的外部服务提供。

## TTFT 与性能证据

服务端从开始发送模型请求到首个非空、可展示的问题正文片段，用服务端单调时钟记录 `model_ttft_ms`。浏览器从“开始面试”或“确认回答”的点击开始，用浏览器单调时钟分别记录首字呈现后的时刻 `first_char_ms`，以及 `speechSynthesis` 第一段有效语音的 `onstart` 时刻 `speech_start_ms`。两台设备的时钟不相减。首段语音会尝试在句读或约 28 个字符时开始合成，不要求等完整问题。录屏仍需核对真正的首字与发声时刻。

“性能记录”页显示真实样本数量、失败数、重试数、成功率及 P50/P95，并可导出逐次 CSV。第一个请求标记为冷启动并单独保留，不从统计中删除；没有自动预热或挑选快请求。所有已完成的成功和失败请求都留在 CSV，重试以 `is_retry` 标记；发生浏览器首字或语音错误的尝试计为失败，浏览器指标缺失时页面不会判定证据齐全。分位数按成功样本升序取第 `ceil(p × N)` 个值。

验收时请用两组样例资料，进行至少 7 场三轮面试，以取得至少 20 次真实提问，覆盖首题与基于确认回答的追问。样例中每组“岗位描述 + 经历摘要”约在 500–1,500 个中文字符的验收范围内；正式测量前以页面实际字数核对。每次走实际语音播报、麦克风回答、文字确认；保留一次完整三轮操作录像，以及同时可见首字与首段播报的性能录屏。导出 CSV，记录模型、温度 `0.5`、`max_tokens=200`、浏览器、Docker 环境，并填写 [验收记录](docs/validation.md) 中的实际结果。不能用示例数字或预生成问题充当证据。

性能页按当前登录账号汇总全部请求。正式测量可以从未做探索测试的另一个预置账号开始；一旦开始，保留该账号的所有成功、失败与重试记录，不选择性删除慢样本。

门槛：成功率至少 95%；模型 TTFT P50 ≤ 2 秒、P95 ≤ 5 秒；页面首字 P95 ≤ 6 秒；首段语音 P95 ≤ 8 秒。外部模型和浏览器环境可能无法达到这些数值，代码不会伪造或缓存问题来通过指标。

有 Python 的环境可用 python scripts/summarize_performance.py interview-performance.csv 对完整导出的 CSV 重新计算统计。脚本不修改记录，缺失指标、重复请求 ID、非法数值或未结束请求不能得到完整达标结论。这个脚本尚未在当前环境执行，真实 CSV 也尚未产生。

## 重建与检查

保留数据卷执行 `docker compose up --build --force-recreate`。重新登录并检查历史问答和进行中进度；切换到另一个测试账号，验证看不到第一账号的记录。可请求 `http://localhost:8080/api/health` 检查后端和数据库。

## 已知限制

当前提供的项目源码不包含真实模型密钥、实际麦克风录音、操作视频或性能测量结果；这些只能在配置可用模型服务并使用有麦克风的浏览器运行后产生。Web Speech API 的识别支持和启动延迟由浏览器及其服务决定。为保证同一轮的生成锁生效，后端配置为单 worker；扩展为多副本时应改为数据库级生成租约。公开测试账号仅用于本地验收，公网部署应更换密码并启用 HTTPS 与 `COOKIE_SECURE=true`。
